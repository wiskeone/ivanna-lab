Краткие рецепты основных сценариев платформы. Полные инструкции и методы — в docs/ репозитория и Swagger / Redoc по REST API.

{% trans "1. Модели" %}

Модели → Загрузить модель: импорт с Hugging Face (repo-id, ревизия, токен в Профиле) или регистрация локального пути. Скачивание идёт фоном (CPU-воркер), статус — в карточке модели.

GGUF: конвертация чекпойнта в GGUF (llama.cpp-скрипты) — «Модели → Конвертация в GGUF». GGUF-чекпойнт можно импортировать и как обычную модель — MoE-скан деквантует его автоматически.

{% trans "2. Мягкий MoE — эксперт домена без дообучения" %}

Тема: 25–30 доменных промптов + столько же контрастных (длины выровнять), опционально 10+10 свежих eval-промптов → гейт валидации (cross cos < 0.5).

Сборка: скан активаций → гейт AUC > 0.85 → steer-патч (α=0.2, слои auto) → eval-гейт → эмбеддинг-роутер. Гейт не пройден — патч не применяется.

Рецепт целиком, α-сетка и ограничения — docs/soft_moe.md в репозитории. Результат — обычный чекпойнт: чат, GGUF, публикация на Hugging Face кнопкой.

{% trans "3. Обучение" %}

Fine-tuning: instruction (LoRA), RAFT (по коллекциям документов), document-тренер. Датасеты — из дистилляции, ручные или с HF Hub. GPU-воркер, выбор устройства, пауза/резюме.

Дистилляция: генерация вопросов и ответов учительскими чекпойнтами → датасет инструкций.

{% trans "4. Инференс и сравнение" %}

Чат-сессии с любым чекпойнтом (transformers in-process или vLLM), сравнение моделей бок о бок, пресеты параметров генерации. Слияния — mergekit (linear/SLERP/TIES/DARE) в «Модели → Слияние».

{% trans "5. RAG" %}

Коллекции документов (PDF/DOCX/HTML/CSV/Excel) → чанкинг → эмбеддинги → FAISS + BM25 гибрид → RAG-чат с привязкой к источникам.

{% trans "6. Оценка" %}

Задачи оценки: несколько моделей × один датасет, сравнение ответов, рейтинги, REST-эндпоинты для программного прогона.
