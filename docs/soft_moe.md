# Мягкий MoE: тематические эксперты без дообучения (v5.2)

Фича превращает **плотную** модель в **«мягкого эксперта» по домену** — без единого
шага градиентного обучения. Направление домена выделяется из активаций и вшивается
в веса rank-one патчем; эмбеддинг-роутер решает, когда грузить эксперта вместо базы.

Метод отработан в лабораторном проекте weight_lab (ноябрь 2026) на Qwen3.5-2B / GGUF:
+9% полноты на домене при −0.7% на general, роутер 20/20, все гейты пройдены.
Здесь — та же техника, портированная на safetensors/transformers для любой архитектуры.

## Идея за 4 шага

1. **Тема** = два набора промптов: доменные (реальные тексты твоего домена) и
   контрастные (быт/код/кулинария/право/спорт), **с выровненными длинами**.
2. **Скан**: прогоняем оба набора через модель, на каждом слое считаем
   `d̂_l = mean_h(домен) − mean_h(контраст)` — направление домена в residual stream.
   Валидация: hold-out AUC проекции активаций на d̂ (гейт > 0.85) + каузальные
   «писатели» (какие модули каких слоёв реально пишут это направление).
3. **Патч** (по умолчанию steer): на выходных матрицах (`down_proj`/`o_proj`/`out_proj`,
   слои по писателям, обычно поздние) —
   `W' = W + α·outer(d̂, ī)/‖ī‖²`, где ī — средний вход модуля на доменных промптах.
   При типичном входе сдвиг выхода ≈ α·‖d̂‖ — то есть α задаёт долю от естественной
   величины направления. Запасной режим `amplify`: `(I + α·d̂d̂ᵀ)W`.
4. **Гейты и роутер**: eval на свежих промптах (base vs expert), центроиды темы в
   эмбеддинг-пространстве, правило `margin cos(домен) − cos(контраст) > 0.08 → эксперт`.

Гейт не пройден → патч не применяется (принцип лабы: каждый патч через гейт).

## Workflow в Ivanna Lab

1. **Новая тема** (`/moe/themes/create/`): вставь 25–30 доменных + 25–30 контрастных
   промптов (по одному на строку) и, опционально, по 10 *свежих* eval-промптов
   (они не должны пересекаться со скановыми — на них честная проверка).
   Выбери эмбеддинг-модель (для валидации и роутера).
2. **Валидация темы** (кнопка на странице темы, CPU): гейт `cross cos < 0.5` +
   плотность домена + предупреждение о балансе длин. Не прошла — пересобери наборы.
3. **Собрать эксперта** (`/moe/jobs/create/`): выбери базовый чекпойнт (плотная
   модель на диске) и тему. GPU-очередь: скан → гейт AUC → патч → (eval) → (роутер).
   На выходе — новый чекпойнт `moe_<тема>_<база>_<дата>`.
4. **Проверка**: на странице джобы — AUC по слоям, слои патча, delta_l1 тензоров,
   сводка eval и тексты ответов base vs expert (ручная выборочная проверка —
   обязательный этап метода; числовые метрики — прокси).
5. **Чат**: эксперт — обычный чекпойнт, доступен в чате/сравнениях; в GGUF —
   штатным конвертером проекта.
6. **HF**: кнопка публикации с авто-карточкой (RU/EN, метод, параметры, гейты).

## Параметры патча

| Параметр | Значение по умолчанию | Когда менять |
|---|---|---|
| mode | `steer` | `amplify` — если steer не дал эффекта (зеркало проверенной абляции) |
| alpha | `0.2` | сетка 0.1 / 0.2 / 0.4; деградация general → α ниже или слои уже |
| layers | `auto` | auto = по каузальным писателям (порог 0.6·медианы топ-8); в лабе вышло L15–23 из 24 |
| position | `last` | `mean` — альтернативная позиция d̂ (в лабе обе работали, last — «состояние готовности ответить») |
| load_mode | `auto` | `int4` (nf4) — скан моделей, не влезающих в VRAM (4B на 4GB); `cpu` — без GPU |
| holdout_seed | `7` | воспроизводимость сплита train/test |

## Что важно знать (выжимка граблей лабы)

- **Длины наборов** должны совпадать по медианам — иначе длина протечёт в d̂.
- **Направления средних слоёв размывают семантику** (в лабе wide-вариант слоёв 14–23
  ухудшил модель) — усилять только доменно-специфичное, доверять писателям.
- **Eval-промпты — только свежие.** Промпты из скана «помнят» центроиды и AUC.
- 20–30 промптов на тему — минимум; «эксперт по паре прогонов» = шум.
- **GGUF-вход**: конвертируется в safetensors (dequant) — требует RAM ≈ размер модели.
  Патч safetensors: пик памяти ≈ размер самого большого shards-файла.
- Скан на 4GB VRAM: Qwen3.5-4B проходит в `int4` (~2.8 ГБ); форварды медленнее,
  патч всё равно делается на CPU из исходных весов.

## Ограничения метода (честно)

- Метрики eval — прокси (длины, повторы, think-утечки), без LLM-judge; финальное
  решение за ручной проверкой текстов.
- Валидировано на одной семье моделей (Qwen3.5, гибрид linear-attention) и одном
  домене; на других архитектурах суффикс-матчинг out-модулей обобщает механику,
  но параметры (α, слои) подбираются заново.
- Это «MoE сверху» (внешний роутер + весовые варианты), не dense→MoE upcycling.
